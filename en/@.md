# @

│ **English (en)** │  **[русский (ru)](<../ru/@.md>)** │

@

The address operator `@` returns the address of an [identifier](<Identifier.md> "Identifier") that is associated with an address (usually a [variable](<Variable.md> "Variable") or [routine](<Routine.md> "Routine"), but also a [label](<Label.md> "Label")). 

Normally, what the value `@` returns is an _untyped_ [`pointer`](<Pointer.md> "Pointer"). If you are handling pointers a lot, and want to mitigate issues with passing references of wrong type’s target, you have to use the [directive](<Compiler_directive.md> "Compiler directive") [`{$typedAddress on}`](</index.php?title=$typedAddress&action=edit&redlink=1> "$typedAddress \(page does not exist\)"). 

Here is an example to demonstrate what produces with untyped pointers valid and functional code, but semantically outputs an erroneous result: 
    
    
    program untypedAddressDemo(input, output, stderr);
    
    procedure incrementIntByRef(const ref: PByte);
    begin
    	inc(ref^);
    end;
    
    var
    	foo: integer;
    begin
    	foo := -1;
    	incrementIntByRef(@foo);
    	writeLn(foo);
    end.
    

It was intended that `0` (zero) gets printed, but the program prints `-256` instead. With `{$typedAddress on}` compilation fails with an incompatible type error. You usually want the latter behavior ([compile-time error](<compile-time_error.md> "compile-time error")) instead of wasting time with hours of debugging. 

## other remarks

  * In [ASCII](<ASCII.md> "ASCII") the character `@` (AT sign): has the value `64`.
  * [PXSC](<PXSC.md> "PXSC") defines the `loc` function as the address-operator.
